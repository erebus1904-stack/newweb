CAPM domain map

Repair CAPM weak areas by domain, not by random question volume.

CAPM shares the project management knowledge base with PMP, but the practice goal is different. Focus on vocabulary, process purpose, delivery approach recognition, agile basics, and business analysis concepts before attempting harder PMP-style scenarios.

Start with the CAPM domain plan

Use the domain study plan to decide which CAPM area should come first. The practice bank is grouped by the current CAPM domain model so you can repair one foundation area before mixing topics.

Fundamentals and core concepts

Use this domain to reinforce project, program, portfolio, stakeholder, deliverable, constraint, risk, issue, assumption, lifecycle, and role language. Review CAPM core concepts after repeated misses.

Predictive methods

Use this domain for scope, WBS, schedule logic, cost baseline, quality, formal acceptance, and change control. Pair practice with the predictive project management guide.

Agile frameworks

Use this domain for Scrum, Kanban, product owner, Scrum Master, backlog, sprint review, retrospective, WIP, servant leadership, and adaptive planning. Review CAPM agile basics.

Business analysis

Use this domain for needs assessment, requirements elicitation, traceability, acceptance criteria, stakeholder analysis, and solution evaluation. Repair misses with the business analysis study guide.

Review missed CAPM questions

After each set, group mistakes by vocabulary, process purpose, delivery approach, agile role, or business analysis term. Use the mistake review method before repeating the same domain.

Connect practice to exam pacing

The CAPM exam is listed by PMI as a 150-question CAPM exam with 180 minutes. Use shorter domain sets first, then practice pacing so explanation review does not replace timed decision practice.

Schedule after your practice plan is stable

When your target date, pacing, and weak-area plan are realistic, use the step-by-step guide to schedule the CAPM exam, find Pearson VUE locations, or choose secure online testing.

Use domains as a repair sequence

Do not treat the four CAPM cards as one random pool. Start with the domain that explains the miss, read the guide for that area, answer a smaller set, and then repeat only the questions that produced uncertain reasoning.

Separate memory misses from method misses

A memory miss means the term or role was not stable. A method miss means you knew the term but chose the wrong process, agile event, or business analysis action. These two misses need different review blocks.

Bridge CAPM knowledge to PMP judgment

When CAPM concepts feel stable, compare them with PMP-style scenarios. The bridge guide explains when to move from term recognition into applied project judgment.

Move to PMP practice only when ready

Use PMP practice after the CAPM domains are no longer producing repeated vocabulary misses. PMP questions ask for role, context, and next action, so weak CAPM foundations should be repaired first.
